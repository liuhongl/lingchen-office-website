# MasterGo 像素级还原

## 质量标准

本项目按旗舰官网标准交付，但内容与视觉使用两条独立真源：用户确认的交互原型决定模块、顺序、逐字文案、指标与交互内容；MasterGo、现有已实现页面和冻结公共组件决定视觉风格。若用户未指定原型，MasterGo 才同时作为内容真源。每个页面必须在 `scope.md` 明确记录两条真源，禁止把视觉复刻口径反向覆盖原型内容。

官网全部页面的语义 SVG 持续授权统一执行 `docs/semantic-icon-generation-rules.md`：后续无需逐页重复询问是否允许生成，但每次仍须先确认不存在可用的 MasterGo 原始图层、用户正式素材或项目正式素材。

官网全部页面的桌面端范围统一执行 `docs/website-desktop-only-scope.md`：当前不建立移动端基线，不做移动端截图或交互验收；每页必须在 `scope.md` 和 `final-validation.md` 明确记录移动端未纳入当前官网范围，禁止据此声称移动端已完成。

若页面属于 `/solutions/products/` 产品专项解决方案迁移批次，还必须读取并执行 `docs/product-solution-prototype-migration-rules.md`；该文件只补充本批次的内容迁移和推进顺序，不再单独定义移动端范围。

## 唯一允许的执行流程

以下流程是门禁，不是建议。任一步缺少证据就停止，不得跳步、猜测或用后续测试替代。

### 1. 建立任务清单

记录页面名称、内容真源链接与版本、视觉真源链接或现有实现路径、目标视口、允许修改范围、公共组件冻结状态和用户确认覆盖项。视觉真源为 MasterGo 时额外记录 `page_id` / `layer_id`。

### 2. 建立分区与基线

- 将 MasterGo 切到 100% 缩放。
- 按视觉区块编号，例如 `01-hero`、`02-problems`。
- 每个区块保存无选中框、标尺和编辑器遮挡的设计截图。
- 没有同视口基线时不得承诺 1:1。

### 3. 建立逐字文案台账

每个文本节点都必须记录：

| 文本 ID | 区块 | 内容真源逐字原文 | 用户覆盖 | 实现位置 | 已核对 |
|---|---|---|---|---|---|

长文案额外记录首句、末句和完整句数。必须保留标点、数字、单位、英文大小写、英文空格、括号和明确换行。

禁止行为：

- 概括、缩写、润色或“优化”内容真源文案。
- 根据语义补写看不清的后半句。
- 未经用户确认，把自己认为的错字改成更合理的文字；疑似错字应单列清单，页面仍按内容真源实现。
- 用截图中可见的前半段冒充完整原文。
- 通过卡片高度正常、页面有内容或构建通过推断文案完整。

看不清时标记 `BLOCKED` 并继续放大或请用户确认。台账未完成，不得开始该区块实现。

### 4. 记录视觉属性

逐元素记录容器尺寸、位置、对齐、间距、字体、字号、字重、行高、字间距、颜色、渐变范围、每侧边框、圆角、阴影、图标和特殊图形。圆点、短弧、轨道、连线和局部加粗必须分别记录，不得以近似样式替代。

必须使用 `templates/visual-ledger.md`。视觉台账未达到零 `BLOCKED`，不得写该区块 JSX/CSS。图标不能只记录“搜索图标”这类语义，必须记录 MasterGo 素材、组件库的精确图标名或导出文件。

#### 图标与图片导出门禁

- 设计稿中可识别、可导出的图标、插画、Logo 和特殊图形，必须从 MasterGo 对应原始图层导出；禁止从设计截图、整页截图或局部截图裁切。
- 矢量素材优先导出 SVG，不得为了方便转成小尺寸 PNG；SVG 必须保留原始 path、stroke、圆角、渐变和透明度。
- 原素材为位图时，导出像素尺寸至少达到 CSS 显示尺寸的 2 倍，优先 3 倍；实现中明确设置宽、高与 `flex:none`，不得放大单倍位图。
- 不得用 Lucide、其他图标库、Emoji、Unicode 字符或近似 CSS 替代 MasterGo 中可导出的正式图标。只有设计稿明确采用同一图标库，或用户明确批准替代时才允许例外，并在视觉台账记录依据。
- 当视觉真源不存在对应正式图标、且用户明确授权按业务语义生成时，允许制作独立语义 SVG；该授权不得替代可导出的 MasterGo 原始图层。视觉台账必须将 `layer_id` 记为“不适用（用户授权语义生成）”，并记录业务语义、参考风格、`viewBox`、描边、颜色、CSS 尺寸、文件路径和 SHA-256。生成图标不得使用机器人、大脑、魔法棒或无语义闪光等模板化“AI 味”符号，除非内容真源明确要求。
- 基础圆点、直线、纯色圆角块可以按设计属性用 CSS 实现；复合图标、品牌图形、手绘路径和特殊轮廓不得近似重画。
- 每个素材必须记录 MasterGo `layer_id`、导出格式、源像素/视图尺寸、CSS 显示尺寸、DPR、文件路径和哈希。导出后以原始尺寸单独打开，检查非透明内容完整、居中、四边安全距和清晰度。
- MasterGo 网页下载按钮不可用或未产生下载事件时，可以直接提取当前选中图层“资源”面板生成的 SVG 源码、原始文件数据或 2×/3× 导出数据。必须记录提取路径并验证数据与当前图层一一对应；面板缩略预览、设计画布截图、放大后的单倍位图不算原始导出数据。
- 自动提取的素材必须核对文件头、真实尺寸、`viewBox`、透明边界、非透明内容、CSS 显示尺寸、有效 DPR 和 SHA-256。有效 DPR 小于 2、路径残缺或来源无法证明时继续标记 `BLOCKED`，禁止插值放大、自动描摹或近似重画。
- 无法访问原始图层、导出失败或素材内容不完整时标记 `BLOCKED`，不得先用占位图继续完成区块。

### 5. 确认公共资产边界

已定稿的 `SiteHeader`、`SiteFooter`、Logo、字体和共享组件视为冻结资产。新页面直接复用，不得复制组件或使用页面级 CSS、`body:has(...)` 等方式覆盖；默认只允许由路由或组件参数改变导航高亮。设计稿与公共基线冲突时先报告，未经用户明确授权不得修改公共资产。

开工前在 `scope.md` 记录公共组件路径、基线截图、视口和文件 SHA-256；交付时重新计算。哈希变化而没有用户授权记录时，任务失败。统一风格只适用于 MasterGo 明确使用同一组件的实例；不得用“全站统一”覆盖设计稿中不同的按钮、渐变或图标。

`BookingModal` 也是冻结公共资产。所有表达预约、体验、演示或合作咨询意图的 CTA，默认通过 `BookingTrigger` 打开同一个 `BookingModal`。统一的是弹窗和行为；CTA 的文字、颜色、渐变、图标、尺寸与位置继续以当前 MasterGo 为准。不得为新页面复制弹窗、另建同类表单或自行维护另一套预约状态。非预约动作的例外必须在 `scope.md` 记录。

### 6. 单区块实现

- 一次只实现一个区块。
- 先实现台账中的原始内容，再实现视觉样式。
- 不新增内容真源或用户确认范围之外的文案、指标、徽标和功能；装饰只取自视觉真源。
- 只修改当前区块直接涉及的文件和样式。
- 每个元素必须能反查到文案台账或视觉台账 ID；不能反查的元素视为擅自新增。
- 禁止先完成整页结构再补台账。上一块内容与视觉验收未通过，不得编辑下一块。

### 7. 单区块内容验收

将 MasterGo 台账与页面实际渲染字符串逐项比较，检查增字、漏句、误录、标点、数字、单位、空格、大小写和换行。源码中存在文字不等于页面完整显示，必须核对渲染结果。

内容未通过时不得进行该区块的完成汇报，也不得进入下一区块。

### 8. 单区块视觉验收

在相同桌面视口生成本地截图，与 MasterGo 100% 基线并排、叠加或做差异检查。至少核对边界、宽高、间距、换行、字重、颜色、渐变、圆角、阴影、图形和交互状态。可测量的关键偏差控制在 2 CSS px 内。

图标验收必须同时包含两层：先单独打开导出文件检查源素材没有空白、残缺或模糊，再在页面同视口截图中检查实际渲染尺寸、位置、颜色、描边和清晰度。只检查文件存在或整页缩略图不算通过。

### 9. 全页回归

- 重新跑一次完整文案台账，不复用单区块“应该已经对”的结论。
- 生成全页同视口截图，核对区块顺序、累计高度、背景衔接和公共头尾。
- 检查 `scrollWidth === clientWidth`。
- 检查页面专属样式没有污染公共组件或其他页面。
- 点击页面全部预约/体验/演示/咨询 CTA，确认均打开公共 `BookingModal`，并在当前桌面目标视口检查关闭、Escape、遮罩、滚动锁定和焦点状态。

用户发现任意一处文案缺失、擅自增加、误录或近似图形后，立即撤销“全页完成”结论，并触发全页同类文本或元素审计，不能只修当前问题。

### 10. 工程验收与交付

运行 `pnpm lint`、`pnpm exec tsc --noEmit`、`pnpm build`、`git diff --check`，最后运行 `pnpm mastergo:check <page-slug>`。最后一项只检查证据是否闭环，不替代人工视觉判断。最终分别汇报内容、视觉、工程三类状态以及所有未验证项。任何工程命令通过都不能替代内容或视觉证据。

## 强制产物目录

每个页面必须保留可追溯证据，建议按以下结构组织：

```text
design-baselines/<page>/
├── scope.md
├── content-ledger.md
├── 01-<section>-mastergo.png
├── 01-<section>-local.png
├── 01-<section>-comparison.png
└── final-validation.md
```

如果现有项目采用其他目录，可以沿用，但必须包含同等证据。

开始新页面时必须优先复制本 Skill 的模板，不得临时省略字段：

- `templates/scope.md`
- `templates/content-ledger.md`
- `templates/visual-ledger.md`
- `templates/seo-geo-validation.md`
- `templates/final-validation.md`

SEO/GEO 的详细规则以项目 `docs/seo-geo-guidelines.md` 为准。该台账与视觉台账并行，但不得为了 SEO/GEO 擅自改变视觉真源或内容真源；需要新增可见内容时先停止并取得用户确认。

## 强制工作方式

- 开发任务的第一条 commentary 必须报告当前门禁、目标区块和已有阻塞项，不能直接宣告开始编码。
- 每完成一个区块，先提交该区块的内容核对结果和同视口对比证据，再进入下一区块。
- 如果当前环境无法读取 MasterGo 研发属性、获得干净 100% 基线或验证正式字体，停止在 G1/G2，不生成近似实现。
- 用户指出任意视觉或文案错误后，将当前区块状态退回未通过，并审计全页同类属性；修正单点不等于恢复完成状态。

## 首页踩坑复盘与防错规则

这些问题已经在首页还原中真实出现过，后续页面必须主动规避：

1. **把运行成功误当成还原成功**
   - 错误表现：页面能打开、构建通过，但 logo 尺寸、Header 右侧文案、Hero 渐变、卡片边框、CTA、Agent OS 节点仍明显偏离设计。
   - 防错动作：每个区块交付前必须有 MasterGo 基线截图、本地同视口截图和人工对照结论；工程验证只证明代码可运行，不证明视觉达标。

2. **用近似样式替代设计细节**
   - 错误表现：设计稿是圆点却做成编号；按钮无边框却加了边框；短弧做成椭圆；Agent OS 节点顶部弧形色块的位置、圆角、重叠关系不对。
   - 防错动作：遇到特殊图形时先拆形状：父容器、伪元素、裁切方式、重叠层级、渐变方向、圆角方向，再写 CSS。不能只看“像一个弧/圆/线”。

3. **没有逐字符核对渐变和字重**
   - 错误表现：“新质生产力”“Agent OS”、按钮文字、指标 `50%+ / 300%+ / 500%+` 的颜色、渐变范围或 font-weight 不对；局部加粗被做成整段统一样式。
   - 防错动作：渐变文字必须标出作用字符、起止颜色和方向；局部加粗必须在 JSX 中拆出对应 span/strong，不允许用父级统一样式代替。

4. **模块背景和宽度被过度复用**
   - 错误表现：多个大模块背景色看起来一样；左右留白偏小；某些设计稿背景如 `#EAF5FF` 被写成近似值；局部出现横向滚动条。
   - 防错动作：每个 section 单独记录背景色、最大内容宽度、左右 padding、上下 padding；截图后检查 `document.documentElement.scrollWidth === document.documentElement.clientWidth`。

5. **擅自补充设计稿没有的内容**
   - 错误表现：加入“结果可量化、价值可验收、支持 POC 验证”等内容真源未出现短句，或用视觉稿旧文案覆盖用户已确认的原型内容。
   - 防错动作：只允许使用页面 `scope.md` 声明的内容真源；看不清的小字必须标记“待确认”，不能为了完整性自行编写。

6. **用户指出一点后没有全区块复查**
   - 错误表现：只修用户指出的局部，比如伪元素 top，却没有继续核对同一模块的背景、圆形、编号渐变、轨道、卡片边框和间距。
   - 防错动作：每次局部修复后，回到当前区块 checklist 完整复查；最终汇报必须区分“已修这个点”和“整个区块已视觉校准”。

7. **长文案只录入前半段但视觉上仍像完整卡片**
   - 错误表现：跨行正文遗漏末尾一句或数句，页面仍能正常布局，lint、类型检查、构建和截图观感均未暴露问题。
   - 防错动作：实现前建立逐区文案清单，为长文案记录首句、末句和完整句数；实现后把内容真源原文与 JSX/数据源字符串逐项对照。发现一处漏文案，强制触发全页文本审计。

8. **在新页面中重复修改已经定稿的公共头尾**
   - 错误表现：使用 `body:has(...)` 或页面专属选择器覆盖 Header/Footer 的高度、容器宽度、Logo、口号、按钮、背景和边框，造成不同页面的公共区域不一致。
   - 防错动作：公共头尾定稿后视为冻结资产；新页面直接复用，只通过路由或组件参数控制导航高亮。设计稿若与公共基线冲突，先报告，未经用户明确授权不得修改公共组件。

9. **用整页缩略图掩盖局部视觉错误**
   - 错误表现：整页并排图在缩小后看起来接近，但局部字体未加粗、背景色缺失、阴影缺失、图标模糊、上下间距不一致仍被标为 `PASS`。
   - 防错动作：全页图只验区块顺序和累计高度；每个区块必须另存可读比例的局部并排图，并逐项记录字体、背景、阴影、图标清晰度和四边间距。未完成局部检查时禁止在 `final-validation.md` 勾选 1:1。

10. **用固定高度和总页高代替内容边界验收**
   - 错误表现：为了对齐全页总高度给 section/card 写死高度，造成正文贴底、模块间距被挤压或后续区块发生累计位移。
   - 防错动作：优先使用内容驱动的 `min-height`；确需固定高度时，必须测量每张卡片最后一行到下边界的距离，并在不同文本行数下验证。全页高度相同不能作为区块通过依据。

11. **未检查文本断行策略和实际字重**
   - 错误表现：`overflow-wrap:anywhere` 把 `01` 拆成两行；标题依赖浏览器默认 `h2/h4` 字重，实际显示比设计稿细。
   - 防错动作：编号、指标、单位和英文短语必须逐项检查 `white-space`、`word-break`、`overflow-wrap`；设计稿中的加粗文本必须记录并验证浏览器计算后的 `font-weight`，不得依赖标签默认样式。

12. **漏验浅色背景、弱阴影和位图 DPR**
   - 错误表现：白色与极浅蓝背景被误判为同色；低透明度阴影在缩略图中消失；32/40px 裁切图在高 DPR 屏幕上被放大而发虚。
   - 防错动作：背景色和阴影必须通过研发属性或像素取样分别记录；局部截图需提高对比度辅助确认弱阴影。位图源尺寸至少达到其 CSS 显示尺寸的 2 倍（优先 SVG/设计稿原始导出），不得把单倍截图裁切当作高清图标交付。

13. **用户指出一类错误后仍只修单点**
   - 错误表现：用户指出一个标题字重、一个卡片底距或一个图标模糊后，只修改该实例，未审计全页同类标题、卡片和图标。
   - 防错动作：反馈触发“同类属性全页审计”：字体反馈检查全部同级标题，间距反馈检查全部同类容器四边，图标反馈检查全部同源位图 DPR，背景/阴影反馈检查全部同层卡片；审计结果写回视觉台账。

14. **图标尺寸正确但裁切内容为空或残缺**
   - 错误表现：导出文件是 24/40px 正方形，实际只截到图标底部、背景一角，甚至整张透明；整页缩略图无法识别该错误。
   - 防错动作：每个导出素材必须以原始尺寸单独打开检查，并制作同类图标联系表；记录非透明内容是否完整、是否居中、四边安全距是否与设计一致。仅通过文件尺寸、文件存在或页面能加载不得标为素材 `PASS`。

15. **Flex 子项把图标拉伸但只检查了宽度**
   - 错误表现：全局 `img { height:auto }` 与 Flex 默认 `align-items:stretch` 共同作用，把 40×40 图标拉成 40×124；错误裁切为空时视觉上不明显。
   - 防错动作：视觉门禁必须批量比较每张图片的 `getBoundingClientRect()` 与 JSX 的 `width/height` 属性，宽或高任一不一致即失败；Flex 卡片图标显式设置宽、高和 `flex:none`。

16. **只在源码中写标题标签，不核对计算字重**
   - 错误表现：页面使用 H2/H3/H4，但全页计算后的 `font-weight` 仍为 400，设计稿中的层级和加粗效果全部丢失。
   - 防错动作：每页验收时导出标题计算样式清单，逐类核对字号、字重和行高；不得把语义标签本身当作加粗证据。

17. **只审计标题字重，遗漏卡片和表格中的强调文本**
   - 错误表现：H2/H3 已加粗，但指标、卡片标题、表头、行标题、状态标签和关键结论仍依赖浏览器默认 `b/strong`，页面局部层级显得发虚。
   - 防错动作：字体门禁必须同时导出 `h1-h6`、`b`、`strong` 及视觉台账标记的强调节点计算样式；逐类记录目标字重和实际字重，禁止只用“全部标题 700”替代逐元素核对。

18. **把相邻模块合并成同一背景，丢失页面节奏**
   - 错误表现：一个 section 内包含两个视觉子区，但实现只给父 section 一个背景色，导致核心能力/平台接入、指标/对比表、商业实效/应用场景之间没有设计稿中的灰白分层。
   - 防错动作：背景台账按视觉子区而不是 DOM section 记录；沿画板纵向至少在每个模块顶部、内容区、模块间留白和底部取样，记录精确分界坐标。一个 DOM section 出现两种背景时使用子容器或精确分段背景，不得为了代码简短合并。若标题、说明段与下方卡片在设计中属于同一背景模块，应先把这些节点放入同一语义容器，再设置背景；禁止让节点留在上一区块，仅靠跨 section 渐变制造“看似同色”的假分组。

19. **图标与文字重复表达同一方向或状态**
   - 错误表现：卡片已有明确向上/向下图标，标题又追加 `↑/↓`，造成视觉噪声和重心重复。
   - 防错动作：默认严格保留设计稿；若用户明确授权视觉优化，先识别图标、文字、颜色是否重复编码同一含义，保留信息层级更清晰且来源正式的一种，并把文案变化写入用户覆盖台账。不得未经授权自行删改。

20. **只检查组件接线，不真实点击交互**
   - 错误表现：源码已经使用 `BookingTrigger` 就把 CTA 标为通过，但当前浏览器未完成 hydration、按钮被遮挡或运行产物失效，点击后没有出现公共表单。
   - 防错动作：每个 CTA 都必须在最终运行实例逐个点击，记录弹窗 DOM 出现、可见性、滚动锁定、Escape/遮罩关闭和焦点恢复。Next.js 开发服务器运行期间执行生产构建后，必须重新检查客户端 hydration；若共享 `.next` 产物导致 HMR/交互失效，完成门禁后重启本地预览再验。

21. **列表语义存在但全局 reset 吃掉圆点和对钩**
   - 错误表现：JSX 使用 `ul/li`，却因 CSS reset 的 `list-style:none` 导致设计稿红点、绿勾全部消失；正文因此看成无层级段落。
   - 防错动作：列表验收必须读取最终 `::marker` 或 `::before` 计算结果并截图；设计使用特定圆点/对钩时显式实现尺寸、颜色、位置和缩进，不能只依赖浏览器默认列表样式。

22. **用固定总高度掩盖末尾内容侵入 Footer**
   - 错误表现：为了让全页高度等于设计画板，末尾合作卡或指引面板超过 section 下边界并与冻结 Footer 重叠。
   - 防错动作：最终门禁批量比较每个 section 最后一个可见子元素的 `bottom` 与 section/footer 的 `top`；任何 `child.bottom > section.bottom` 或 `content.bottom > footer.top` 都失败。设计主体未包含公共 Footer 时允许总页高增加，禁止靠裁切或重叠强行对齐画板总高。

23. **正式图标文件存在但内容属于其他图层**
   - 错误表现：文件名和尺寸看似正确，实际内容是一段文字、邻近图层或错误区域；页面因此渲染出无法辨认的图形。
   - 防错动作：素材联系表除完整性和 DPR 外，还必须逐项核对“内容语义与目标元素一致”；文件名不能作为证据。标题图标、刷新图标、状态图标等在页面截图中必须与设计局部并排确认后才能 PASS。

24. **只验证 `localhost`，遗漏用户实际使用的本地域名**
   - 错误表现：页面服务端 HTML 正常、源码也已接入公共交互组件，但用户通过 `127.0.0.1` 访问时 Next.js 阻断开发资源跨来源连接，导致 hydration 失效，所有按钮都像“不可点击”。
   - 防错动作：最终交互门禁必须使用用户提供的完整 URL（协议、主机、端口、路径）验证，并检查控制台的 HMR/hydration 错误。项目需要同时支持 `localhost` 与 `127.0.0.1` 时，在 `next.config` 明确配置允许的本地开发来源，重启开发服务后再逐个点击公共头 CTA 与页面 CTA；不能用源码接线或另一主机名的成功结果替代。

25. **原始图层可导出时仍用手绘、字符或旧位图代替**
   - 错误表现：刷新、多人、电话、邮件等图标在 MasterGo 中有独立矢量图层，代码却使用 Unicode、内联手绘 SVG、图标库或模糊 PNG，语义相似但路径、描边和留白均不一致。
   - 防错动作：先选中目标图层并直接导出 SVG，记录 `layer_id`、`viewBox`、CSS 尺寸和 SHA-256；正式 SVG 未取得前对应元素保持 `BLOCKED`。完成后搜索源码，确保不存在仍会渲染或作为回退的近似字符、data URI 或错误旧素材。

26. **用任意渐变断点代替真实模块背景边界**
   - 错误表现：父 section 用固定像素渐变模拟灰白分区，但断点没有绑定相邻子区的实际 `bottom/top`，导致灰底侵入下一组卡片，看起来像模块重叠。
   - 防错动作：在同视口读取前一区块 `bottom`、后一区块 `top` 与背景分界坐标，三者必须按设计对应；内容高度变化后重新测量。禁止只凭全页观感或总高度调整渐变断点。

27. **标题图标只检查尺寸，遗漏与模块顶部的垂直距离**
   - 错误表现：图标本身宽高正确，但紧贴背景分界或容器顶部，破坏设计稿的节奏和标题层级。
   - 防错动作：视觉台账必须记录标题图标 `top - section.top`、图标与标题间距以及标题到下方内容的距离；同视口截图中逐项测量，不能仅验证图标为 40×40 或“已经显示”。

28. **独立模块用单边外边距串联，导致上下留白不对称**
   - 错误表现：卡片或长面板虽然视觉上像独立模块，代码却只给它设置 `margin-top`；前后区块高度变化后，上方留白与下方留白失衡，甚至卡片贴住背景分界。固定高度卡片内部也只设置普通 padding，导致不同文本长度的内容整体偏上。
   - 防错动作：独立模块必须同时测量 `content.top - module.top` 与 `module.bottom - content.bottom`，设计为对称时两者必须相等；相邻独立模块用明确的模块 padding/gap 表达，禁止依赖上一元素的偶然高度。固定高度卡片若设计内容垂直居中，显式使用纵向 Flex/Grid 居中，并逐卡验证首元素顶部余量等于末元素底部余量。

29. **用一个父 section 的分段渐变冒充多个独立大模块**
   - 错误表现：原因卡、核心能力、差异优势和技术底座都放在同一父 section 中，再用多个渐变断点模拟灰白背景。任一内容高度变化都会让背景错位，而且 DOM 无法反映设计稿的真实模块归属。
   - 防错动作：设计稿中拥有独立背景范围和上下留白的区域必须建立独立 section/语义容器，由该容器直接拥有背景与 padding；禁止用一个跨多模块的固定高度父容器或渐变断点代替。长文本面板默认使用 `height:auto`，只有设计证据明确要求固定高度且内容安全距通过时才允许固定。

30. **共享弹窗从触发按钮所在区块继承页面样式**
   - 错误表现：同一个 `BookingModal` 从 Header 打开正常，从深色 Hero 或居中 Closing 打开后却继承白色文字、居中排版或其他页面级样式，看起来像两套弹窗。
   - 防错动作：共享 Overlay 必须通过 Portal 挂载到 `document.body`，不能嵌套在触发按钮所在 section 中；验收时分别从 Header、Hero、正文和 Closing 触发，比较弹窗父节点及标题颜色、面板背景、文本对齐等计算样式。

31. **只核对卡片外框，遗漏内部视觉语法**
   - 错误表现：卡片尺寸和总页高接近设计，但标签药丸、编号底色、标题圆点、局部强调色、弱边框和阴影缺失。
   - 防错动作：每张卡片按“容器、图标、标签、标题、正文、局部强调”六层建立台账；局部截图逐层核对，不允许用卡片整体 MAE 或总页高替代内部元素验收。

32. **React 文本未拆节点导致局部强调无法还原**
   - 错误表现：设计稿只有“AI工作伙伴”或每段首句为蓝色/加粗，实现却把整段放在一个文本节点里，最后只能统一颜色和字重。
   - 防错动作：视觉台账标记的局部强调必须在 JSX 中拆成 `strong/span`；验收读取该节点最终 `color`、`font-weight`，不能只确认父段落样式。

33. **图标文件存在但来源映射错误**
   - 错误表现：下载目录中存在同名 `组 31.svg`、`组 32.svg` 等文件，就按文件名猜测用途，导致自动化文书、标题图标和价值卡图标串用。
   - 防错动作：每次选中目标图层后立即记录“页面区块 + 选中图层 + 实际预览 + 新文件名 + SHA-256”；遇到下载重名必须立刻按业务语义重命名，导出后制作联系表逐枚与设计局部截图对照。禁止仅凭 MasterGo 自动文件名复用旧下载。

34. **用户指出多个视觉缺失后仍用全页缩略图验收**
   - 错误表现：全页缩略图里看不清 8–40px 图标、标签背景、圆点和局部字色，却仍将区块标记为通过。
   - 防错动作：用户指出任意一项小元素后，撤销全页视觉完成结论；针对所有同类小元素输出 DOM 数量、资源路径和计算样式清单，并保存可读比例局部截图。列表数量与台账不一致时直接失败。

## 完成门槛

- 所有文本节点均有已声明内容真源的原文证据和实现位置；原文无擅自增删。
- 长文案的首句、末句、完整句数、标点、数字、英文空格和大小写已逐项核对。
- 关键字体颜色和渐变逐字符对应。
- 图形类型一致，例如圆点不能替换为编号。
- 所有设计图标均能反查到 MasterGo 原始图层和导出文件；没有截图裁图、低分辨率放大或未经确认的图标库替代。
- 相同视口下主容器、卡片和关键元素位置无肉眼明显偏移。
- 交互状态完整且不改变设计稿默认视觉。
- 新页面没有页面级 Header/Footer 样式覆盖；公共区域除导航高亮外与已确认基线一致。
- 所有预约类 CTA 均复用 `BookingTrigger` 与公共 `BookingModal`，没有重复弹窗实现。
- lint、类型检查、生产构建全部通过。
