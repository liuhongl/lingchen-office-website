# 产品专项解决方案原型迁移规则

## 1. 适用范围

- 生效日期：2026-07-22。
- 适用于 `/solutions/products/` 下的七个产品专项解决方案页面：Sales in、Social Grow、Mine GEO、AI获客Harness、Recov AI、DeepDoc、DeepLaw。
- 本规则是当前产品专项解决方案迁移批次的强制规则，不自动扩展到首页、关于灵宸、综合解决方案、产品详情、客户案例或研究院页面。
- 页面专项增删、排序和措辞覆盖继续记录在各自 `design-baselines/<page>/scope.md`，不得从一个页面推导到其他页面。

### 官网级图标授权引用

- 语义 SVG 授权不是本批次专属规则，统一执行 `docs/semantic-icon-generation-rules.md`。
- 用户已将授权扩展到本官网仓库全部正式页面，后续无需逐页重复询问。
- 本文件只负责七个产品专项解决方案页面的内容迁移和推进顺序；整个官网的桌面端范围统一执行 `docs/website-desktop-only-scope.md`。

## 2. 内容与视觉真源

- 内容真源：用户指定的 Google AI Studio 交互原型。页面模块、顺序、逐字文案、指标和交互内容以原型为准。
- 视觉真源：现有官网已确认的设计系统、冻结公共组件、当前同类页面风格以及可用的 MasterGo 正式图层。
- 原型只决定“有什么内容”，不要求复刻原型自身的视觉风格。
- 现有代码只作为结构和样式迁移参考，不得反向覆盖原型内容。
- 疑似错字单列清单；用户已于 2026-07-22 批量确认：明显错别字和明显漏标点按候选建议修正，有歧义的内容继续保留原型原文。
- 每页写代码前必须完成 `scope.md`、`content-ledger.md`、`visual-ledger.md` 和 SEO/GEO 台账；内容或视觉存在 `BLOCKED` 时不得实现对应区块。

## 3. 桌面端优先与移动端范围

- 当前整个官网只实现和验收桌面端，统一执行 `docs/website-desktop-only-scope.md`。
- 产品专项页面仍需在 `scope.md` 记录实际桌面目标视口；没有专项约定时默认使用 `1280 × 720`。
- 移动端未纳入当前官网范围，不作为产品专项页面冻结的阻塞项，也不得产生移动端完成结论。

## 4. 图标来源优先级

1. 视觉真源中存在可识别、可导出的正式 MasterGo 图标时，必须导出原始 SVG，不得自行重画。
2. 项目中已有经过验收、语义一致且属于同一视觉体系的正式图标时，可以复用，但必须在视觉台账记录源文件和复用依据。
3. 原型需要图标、视觉真源没有对应正式素材时，按 `docs/semantic-icon-generation-rules.md` 的官网级授权制作新的语义 SVG。

用户授权生成不构成绕过正式素材门禁的理由：只要存在对应 MasterGo 原始图层，仍优先使用原始图层。

## 5. 语义 SVG 生成规则

- 图标必须先定义业务语义，再绘制图形；禁止先选一个通用图标再反向解释。
- 参考项目已确认 MasterGo 图标的视觉语言：简洁轮廓、克制配色、统一视觉网格、圆角端点和圆角连接，描边粗细与同区块图标一致。
- 避免机器人头像、AI 大脑、魔法棒、无语义闪光、随机星芒、渐变球等明显“AI 味”符号，除非内容真源本身明确要求。
- 默认制作独立 SVG 文件，不使用 Emoji、Unicode 字符、截图裁图或未经登记的第三方图标库。
- 同一组图标必须统一 `viewBox`、安全边距、描边、端点、颜色层级和实际 CSS 尺寸；不同组可以按所在组件尺寸分别定义。
- 图标只表达已有业务语义，不新增卖点、指标、功能或事实。
- 装饰性图标使用空 `alt`；只有图标本身承载页面未重复表达的信息时才提供准确替代文本。

## 6. 图标证据与验收

每个新制语义 SVG 必须在 `visual-ledger.md` 记录：

- 对应区块、卡片标题和业务语义。
- 来源类型：`用户授权语义生成`。
- 参考的既有图标组或 MasterGo 视觉语言。
- `viewBox`、源尺寸、CSS 显示尺寸、描边宽度、颜色和文件路径。
- 文件 SHA-256。
- 原始文件完整性、居中、安全边距和页面实际渲染检查结论。

验收必须同时通过：

1. 单独打开 SVG，确认没有空白、残缺、错误裁切或语义错配。
2. 在桌面目标视口检查实际宽高、位置、清晰度、颜色和同组一致性。
3. 批量核对图标数量与台账一致，浏览器中全部加载完成。

## 7. 页面推进顺序

1. 从原型提取完整 DOM 文本并建立内容快照。
2. 输出现有页面与原型的逐项差异清单并归档；用户已授权本批次不再逐页等待审批。
3. 按用户确认的批量口径记录删除、保留、纠错和视觉例外；只有原型不可读、来源冲突或高风险事实不确定时暂停确认。
4. 按单区块完成内容、视觉与图标实现。
5. 每个区块完成桌面同视口内容与视觉双验收后再进入下一区块。
6. 全页完成后执行桌面回归、预约 CTA 回归、SEO/GEO 台账和工程门禁。
7. 用户确认桌面效果后冻结页面，再进入下一个产品专项解决方案页面。
