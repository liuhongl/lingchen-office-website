# 官网桌面端优先范围规则

## 1. 当前授权范围

- 生效日期：2026-07-22。
- 用户已明确确认：当前整个官网暂不考虑移动端，只实现和验收桌面端。
- 本规则覆盖本仓库当前和后续新增的全部正式官网页面，包括首页、产品矩阵及详情、产品专项解决方案、综合解决方案、关于灵宸、客户案例、研究院和联系页。
- 本规则持续有效，直到用户明确重新把移动端纳入范围。

## 2. 当前桌面端交付要求

- 每页必须在 `scope.md` 记录桌面目标视口；没有页面专项约定时默认使用 `1280 × 720`。
- 内容、视觉、图标、CTA、SEO/GEO 和工程门禁继续完整执行，不能因为移动端暂缓而降低桌面端质量。
- 视觉验收、浏览器交互验收和最终截图只针对已声明的桌面视口。
- 每页 `final-validation.md` 必须明确写明“移动端未纳入当前官网范围”，不得把未做移动端误记为阻塞项。

## 3. 移动端暂缓边界

- 当前不建立移动端设计基线，不做 390px 或其他移动视口截图对比，不做移动端交互、触控、弹窗和横向溢出验收。
- 不新增为了移动端而设计的布局、断点、组件变体或内容折叠逻辑。
- 已存在的响应式代码和历史移动端证据可以保留，不为本轮主动删除；但不得据此宣称当前移动端已实现、已回归、已视觉校准或 1:1。
- 如果桌面改动可能影响已有移动端，应在台账记录风险，但不在当前范围内展开移动端修复或重构。
- 移动端未纳入范围不代表允许故意破坏已有代码；禁止为了桌面对现有响应式代码做无关的破坏性清理。

## 4. 未来恢复移动端

- 用户重新授权移动端后，必须把移动端作为独立阶段处理。
- 每类页面重新建立目标设备、视口、设计基线、内容换行、导航、弹窗、触控和横向溢出验收。
- 桌面端通过结论和历史移动端截图不能替代新的移动端验收。
